# Submission checklist

Owner: the team's authorized project representative. This checklist records tasks, not completion of the Studio form.

## Repository and demo

- [x] Public repository and live demo linked from the README.
- [x] English judge guide, architecture, methodology and source provenance present.
- [x] Three audiences, ten explanation locales, protected plan values and labelled fallback implemented.
- [x] Original synthetic scenario, historical-derived profiles and synthetic physical estimates distinguished.
- [x] Official Hudl Statsbomb logo/credit and SkillCorner MIT notice retained.
- [x] Accepted 46-case Azure artifact at 980bde2 preserved and linked.
- [x] Arsenal-only recording route and English narration script prepared.
- [ ] Submission-readiness branch reviewed, merged/deployed, and the resulting SHA checked live.
- [ ] New English count-neutral statistic templates checked with strict live acceptance after deployment.
- [ ] Data publication permissions resolved for retained inputs/derived profiles; see DATA_SOURCES.md. Renaming them does not complete this item.

## Video

- [ ] Record the actual Azure app, Arsenal perspective, readable layout and English narration.
- [ ] Show a recommendation, a different/rejected option, contextual explanation and another explanation language.
- [ ] Show a late tactical action without implying that inspection executes it.
- [ ] Add corrected English captions; check player names, xG and Foundry.
- [ ] Export MP4, target 1:45–1:50, strictly less than two minutes.
- [ ] Check the full export, including sound and text, and upload to a supported public video service.
- [ ] Open the video without login; add its real URL to the README and submission.

## Project page

- [ ] Confirm all team memberships and the authorized representative.
- [ ] Paste the English pitch, description, Microsoft/Azure usage and testing instructions from SUBMISSION.md.
- [ ] Include the public repository, live demo and public video links in the correct fields.
- [ ] Use accurate categories and claims: Foundry is implemented; autonomous multi-agent orchestration and calibrated win probabilities are not.
- [ ] Include required source/asset acknowledgements and resolve permission questions before asserting rights.
- [ ] Submit before 28 October 2026 at 08:59 Israel; aim for 27 October evening.
- [ ] Save confirmation and verify the submitted links. Keep Azure available through the judging period.

## Optional project housekeeping

- [ ] Decide a team-approved code license if public reuse is intended. Public visibility alone is not an open-source license; no blanket license should be applied to third-party data.
- [ ] Have a native speaker read one translated explanation and a football reviewer inspect 3–5 plans.
